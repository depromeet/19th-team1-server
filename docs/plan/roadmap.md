# 로드맵

프리런칭(12/12)까지의 에픽·스토리와 진행 순서다. 무엇을 만드는지는 [scope.md](scope.md), 스토리 하나를 진행하는 방법은 아래 "진행 방법"을 따른다.

## 정보를 두는 곳

같은 내용을 두 곳에 적지 않는다.

| 정보 | 두는 곳 |
| --- | --- |
| 무엇을, 왜, 완료 조건 | GitHub 이슈 |
| 상태 (열림·닫힘, 담당, 연결된 PR) | GitHub 이슈. 이 문서에는 상태를 적지 않는다 |
| 순서, 선행, 주차, 기능명세서 ID | 이 문서 |
| 세부 작업과 참고 문서 | `stories/<스토리 ID>-<영문-설명>.md`. 착수할 때 만들고, 그 스토리의 PR에서 지운다 |

## 진행 방법

1. **고르기**: 내 담당이고, 이슈가 열려 있고, 선행 스토리의 이슈가 모두 닫힌 스토리 중 주차가 가장 이른 것을 고른다. 상태는 `gh issue view <번호>`로 확인한다.
2. **착수**: `main`에서 브랜치를 만들고([conventions.md](../conventions.md)), [stories/_template.md](stories/_template.md)를 복사해 스토리 파일을 만든다. 이슈의 완료 조건을 읽고 세부 작업을 채운다. 사람이 계획을 확인한 뒤 구현한다.
3. **구현**: 세부 작업을 하나씩 끝내고 체크한다. 테스트를 먼저 쓴다.
4. **마무리**: 이슈의 완료 조건을 모두 확인하고, 실행한 검증 명령과 결과를 PR에 적는다. 스토리 파일을 지우고 PR 본문에 `Closes #이슈번호`를 적는다.

## 계획이 바뀔 때

팀 결정이 바뀌면 [scope.md](scope.md) → 이 문서 → 진행 중인 스토리 파일 → GitHub 이슈 순서로 한 PR에서 고친다. 영향받는 스토리는 scope.md의 기능명세서 ID와 "결정 대기" 표로 찾는다. 진행 중인 스토리가 영향을 받으면 수정이 반영될 때까지 멈춘다.
