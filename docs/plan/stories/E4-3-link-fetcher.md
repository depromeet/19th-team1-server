# E4-3 플랫폼별 링크 수집기

이슈: #61 · 에픽: E4 자동 정리 · 담당: 승환 · 명세: —

## 세부 작업

한 줄이 '실패하는 테스트 하나 → 통과할 만큼만 구현'이다. 테스트는 수집기 인터페이스 `fetch(url)` 하나에서 한다(`HttpLinkContentFetcherTest`). 괄호는 이슈 완료 조건의 순번이다.

- [x] 1. 유튜브 영상 주소면 oEmbed로 제목·채널·썸네일을 돌려준다 (1)
- [x] 2. youtu.be·shorts·live·embed·모바일 주소도 같은 영상으로 요청한다 (1)
- [x] 3. 요청하지 않는 곳은 요청 없이 '요청 안 함' 수집 누락과 최종 주소를 돌려준다. 수집 수준은 `LINK_MEMO`다 (4)
- [x] 4. 그 외 페이지에서 제목·설명·본문·대표 이미지를 뽑는다 (2)
- [x] 5. 블로그 호스트(네이버 블로그·티스토리·벨로그·브런치·미디엄)는 `BLOG`, 노션은 `NOTION`으로 정한다. 목록에 없는 블로그는 페이지의 JSON-LD가 블로그라고 밝히면 `BLOG`, 아니면 `OTHER`다. `Platform`을 정리한다 (2, 7)
- [x] 6. 비공개 노션은 주소의 제목 조각을 제목으로 쓰고 '막힘' 수집 누락을 같이 돌려준다 (2, 6)
- [x] 7. 네이버 블로그는 모바일 주소로 받는다 (2)
- [ ] 8. http·https와 포트 80·443만 받고, 사용자 정보가 든 주소(`user:pw@host`)는 받지 않는다. 사설망·메타데이터 주소로는 요청하지 않는다. 처음 주소, 리다이렉트된 주소, 다시 해석한 DNS를 모두 본다. 웹 페이지 요청(Apache HttpClient 5, 5번에서 도입)의 DNS 해석기에서 연결 직전에 IP를 검사한다 (5)
- [ ] 9. robots.txt가 막으면 받지 않는다. 호스트마다 24시간 기억한다 (5)
- [ ] 10. 단축 주소를 풀고 최종 주소로 플랫폼을 정한다. 리다이렉트는 5번까지 따라가고, 넘으면 수집 누락으로 돌려준다. 리다이렉트를 따라갈 때 쿠키가 필요하면 한 링크를 받는 동안만 쓰는 저장소를 둔다 (3)
- [x] 11. 외부 오류는 `LinkError` 예외로 바꾼다: 없는 글(404·410), 막힘(401·403·그 밖의 4xx), 호출 한도(429), 받을 수 없음(5xx·시간 초과·연결 실패). 유튜브 oEmbed도 같다. 노션의 404만 예외가 아니라 '막힘' 수집 누락이다(비공개와 없는 페이지가 구분되지 않음) (6)
- [ ] 12. 길이를 맞춘다: 제목 500자, 설명 2,000자, 본문 6,000자, 2,048자가 넘거나 http·https가 아닌 이미지 주소는 버린다. 응답은 앞 3MB까지만 읽고 진행한다. HTML이 아닌 응답은 받지 않고 그 이유를 수집 누락으로 돌려준다. 한 링크에 쓰는 전체 시간에 상한을 둔다(조금씩 계속 보내는 서버, 연결 풀 대기 포함) (2)
- [ ] 13. 수집기를 빈으로 등록하고 설정 기본값을 둔다. 봇 이름은 임시 기본값으로 둔다. 웹 페이지 연결 풀 크기는 워커 동시성에 맞추고 쉬던 연결은 쓰기 전에 검사한다 (1~6)
- [ ] 14. meta author가 없으면 주소의 계정(네이버 blogId, 벨로그 `@아이디`, 티스토리 하위 도메인)을 작성자로 쓴다 (2)
- [ ] 15. architecture.md를 고친다: 8절 경계 표(외부 오류는 `LinkError` 예외, 받지 않기로 한 경우는 수집 누락, 카테고리는 정하지 않음), 10절 결정 세 줄(카테고리를 정하지 않음, 유튜브는 oEmbed만, robots.txt를 지키고 요청하지 않는 곳은 요청하지 않음), 11절 10번 삭제 (8)

## 참고

- 규칙: `.claude/rules/architecture.md`, `.claude/rules/external.md`(타임아웃, 오류 변환, 로그), `.claude/rules/testing.md`(가짜 HTTP 서버, 고정 시계)
- 문서: `docs/architecture.md` 8절 경계 인터페이스(`LinkContentFetcher`)·7절 `saved_item.platform`, `docs/plan/scope.md` "플랫폼별 수집 수준"·결정 대기 1
- 결정(11/22 grill)
  - 수집 결과: 최종 주소, 플랫폼, 수집 수준, 제목, 작성자, 설명, 본문(저장하지 않음), 대표 이미지 주소, 수집 누락
  - 수집기는 `originalUrl`을 받는다. 저장물 주소는 바꾸지 않는다
  - 수집기는 카테고리를 정하지 않는다. 주소 카테고리는 분석(E4-6)이 정한다
  - 외부 오류(시간 초과, 오류 응답, 호출 한도 초과)는 `LinkError` 예외로 던진다. `GeminiLlmClient`·`KakaoOAuthClient`와 같은 방식이고 `.claude/rules/external.md`를 따른다. 받지 않기로 한 경우(요청 안 함, 비공개 노션, robots 금지, 위험한 주소, HTML 아님, 리다이렉트 5번 초과)만 수집 누락 값으로 돌려준다. 작업 실패 코드와 다시 할지는 E4-6이 `LinkError` 값으로 정한다
  - 수집 수준은 결과가 아니라 경로로 정한다
  - 유튜브는 oEmbed만 쓴다(JDK HttpClient 그대로). 영상이 아닌 유튜브 주소(채널, 재생목록 등)는 요청하지 않고 YOUTUBE·LINK_MEMO·'요청 안 함'을 돌려준다(11/22 리뷰 뒤)
  - 요청하지 않는 곳은 도메인 단위로 막는다. 대소문자, 끝의 점, 하위 도메인이 달라도 같다. 목록(SNS, 지도, 쇼핑·선물, 네이버 뉴스)은 지금 넣고, 회의에서 바뀌면 줄을 고친다. 네이버 뉴스는 robots.txt가 모든 봇을 막는다(11/28 확인). 네이버 지도는 조사 전이라 임시로 넣었다. 다른 뉴스 사이트는 그 외 웹 페이지로 받는다
  - 유튜브는 `youtube.com`·`youtube-nocookie.com`과 그 하위 도메인, `youtu.be`다. 영상 주소는 watch·youtu.be·shorts·live·embed와 옛 형태 `/v/{id}`다. 경로 뒤에 `&`로 붙은 값(`/v/{id}&hl=en`)은 잘라 낸다. 영상 ID가 11자 형식이 아니거나 재생목록·채널 라이브 임베드(`videoseries`, `live_stream`)면 영상이 아닌 주소로 본다
  - 네이버 블로그 모바일 주소로 바꾸는 것은 `blog.naver.com`·`m.blog.naver.com`의 글 주소(`/{id}/{logNo}`, `PostView`·`PostList` 화면의 `.naver`·`.nhn`, `/{id}?Redirect=Log&logNo=`)이고 블로그 아이디가 영문·숫자·`_`·`-`, 글 번호가 숫자(0~9)일 때뿐이다
  - 노션 도메인은 `notion.site`·`notion.so`·`app.notion.com`이다. `app.notion.com`은 노션이 비공개 페이지를 브라우저에서 여는 주소다(11/19 직접 호출)
  - 웹 페이지 요청은 자동 재시도와 쿠키 저장을 끈다. 재시도는 작업 재시도가 정한다
  - 본문 추출은 #47 방식 그대로 둔다(header·form 통째 제거). 수동 확인에서 본문을 잃는 페이지가 나오면 고친다
  - `Platform`은 YOUTUBE·BLOG·NOTION·OTHER(11/21). 테스트 위치는 `fetch(url)` 하나
  - 목록에 없는 호스트도 페이지의 JSON-LD 최상위 `@type`(`@graph` 항목 포함, 전체 주소 형태 포함, 문자열 안 줄바꿈·끝 쉼표·JSON 안 주석·HTML 주석과 CDATA 감싸기·값 뒤 `;` 허용)이 `BlogPosting`·`Blog`면 BLOG다. 안쪽 객체(작성자 등)의 타입은 보지 않는다. RSS·generator·og:type은 #47 링크에서 뉴스에도 있어 쓰지 않는다(11/22 측정: RSS 뉴스 3/4, WordPress 표시 뉴스 1, BlogPosting 블로그 1/3·뉴스 0/4)
